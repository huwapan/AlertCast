# 000b 時間指定予定を文字で入力して登録する

- ストーリー：[docs/storymap.md](../docs/storymap.md) の「入力 > 予定を入力する > 文字で入力」と「^ 期限を入力」
- 期間：2026-11-19
- 使った道具：GitHub Copilot（Copilot CLI）
- 状態：完了（main に反映済み）
- この計画書について：Claude Code を使い始める前の作業を、2026-11-26 にあとから書き起こした。元にしたのは **Git の履歴** と、PC に残っていた **Copilot CLI の会話記録**。記録から読み取れないことは「（推測）」と書いている。

## 背景
- 土台（[000a](000a_project-setup.md)）ができたので、次に何をするかを Copilot に相談した。
- Copilot の提案は「予定の登録 → SQLite に保存」から作ること。画面とテーブルはあるが、その2つをつなぐ処理がまだなかったため。
- 進め方は **ウォーキングスケルトン**（各機能の最小限を、画面から DB まで端から端まで通す）にすると決めた。

## 決めたこと
- 最初の機能は **時間指定予定の登録** だけにする。入力するのはタイトル・開始日時・終了日時・優先度。終日予定・変更・削除・一覧は後回しにする。
- ファイルの役割を分ける。
  - `public/schedule-edit.html`：入力フォーム
  - `public/register-schedule.php`：ブラウザーから呼べる入口（**公開エンドポイント**）。`src/` の処理を呼ぶだけ
  - `src/schedule-create.php`：入力の検証と DB への保存
  - `src/Data.php`：DB への接続（[000a](000a_project-setup.md) で作成済み）
- 日時は日本時間の `YYYY-MM-DD HH:MM:SS` に変換して保存する。
- 登録に成功したら、`303` でフォームの画面に戻し、「時間指定予定を登録しました。」と表示する。
- `pdo_sqlite` を有効にする手順を README に書く。
- storymap の「^ 期限を入力」も、このとき一緒に完了にした。時間指定予定の「終了日時」を期限とみなしたと思われる（推測）。期限で終わらせる予定（`deadline`）の登録画面はまだない。

## 失敗したことと修正したこと

### 1. 一度にまとめて作りすぎた
- 起きたこと：Copilot がフォームと保存処理をまとめて作ってしまい、1つのコミットにするには大きすぎた。
- 修正：「もっと細かく機能ごとに commit したい」と伝えて作業を止めた。Copilot からは「フォームだけ」「入力検証だけ」「DB 保存だけ」のように分けられると説明を受けた。
- 教訓：AI に頼む前に、今回作る範囲を小さく決めて伝える。

### 2. 相談したかっただけなのに、実装まで進められた
- 起きたこと：「ウォーキングスケルトンの実装からしたい」と伝えたところ、Copilot がすぐにコードを書き始めた。本当は、どの機能から始めるかを聞きたかっただけだった。今あるファイル（`src/schedule-create.php` など）も十分に考えに入れていなかった。
- 修正：作業を止めて、「今あるファイルを考慮して作成してください。どの機能から実装するか聞きたかっただけです」と伝えた。Copilot は自分が追加した分を取り消し、相談に答え直した。
- 教訓：相談したいのか、作ってほしいのかをはっきり伝える。「まず案だけ教えて」のように言うとよい。

### 3. 保存処理を `src/` に置くと、ブラウザーから呼べなかった
- 起きたこと：保存処理は `src/schedule-create.php` にあるが、Web サーバーが公開するのは `public/` だけなので、フォームから直接呼べない。README でも、一時 `public/` に登録処理があると書いていた（`ead4d22`）。
- 修正：`public/` に「入口」のファイルを作り、そこから `src/` の処理を呼ぶようにした（**公開エンドポイント**）。README の説明も実際のファイルの場所に合わせた（`424e9ad`）。
- 教訓：ブラウザーから呼ぶファイルは `public/`、中の処理は `src/` に分ける。`src/` を直接公開しないので、内部の処理を外から触られにくい。

### 4. 入口のファイル名が中の処理と同じで、紛らわしかった
- 起きたこと：最初は入口を `public/schedule-create.php` にしたので、`src/schedule-create.php` と同じ名前になった。
- 修正：「同名にした理由は何？」と確認したうえで、入口を `public/register-schedule.php` に変えた。フォームの送信先と README も合わせて直した。
- 教訓：役割が違うファイルには、違う名前を付ける。

### 5. 登録すると PHP の結果ページが表示されたままだった
- 起きたこと：最初は、登録に成功すると PHP が「登録しました」のページ（ステータス `201`）を表示して終わっていた。
- 修正：「登録完了を告げて元の HTML に戻すべきじゃない？」と指摘した。`303` でフォーム画面（`schedule-edit.html?registered=1`）に戻し、画面の上に完了メッセージを出すようにした。再読み込みしても二重に登録されない。
- 教訓：フォームを送ったあとはリダイレクトで元の画面に戻す（PRG パターン：POST → Redirect → GET）。

### 6. ボタンを押しても PHP のコードが表示されるだけだった
- 起きたこと：ブラウザーで登録ボタンを押すと、PHP が実行されず、ファイルの中身がそのまま表示された。
- 原因：ページを `file://` や VS Code の Live Server で開いていた。どちらも PHP を実行できない。
- 修正：プロジェクトのルートで `php -S 127.0.0.1:8000 -t public` を実行し、`http://127.0.0.1:8000/schedule-edit.html` から開くようにした（README の「ローカルでの起動」）。
- 教訓：PHP のページは、PHP を実行できるサーバー経由で開く。
