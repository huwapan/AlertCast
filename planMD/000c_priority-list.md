## 失敗したことと修正したこと

### 1. HTML のページでは、データベースの予定を表示できなかった
- 起きたこと：閲覧ページは最初 `show-table.html` として作っていた（`cd29f76`）。HTML はデータベースを読めないので、登録した予定を一覧にできない。
- 修正：PHP のページ `show-table.php` を作って一覧を表示し、ホームのリンクを付け替えた。`show-table.html` は削除した（`3d7b0e6`）。
- 教訓：データベースの中身を表示するページは、最初から PHP で作る。同じことは、あとでホームを `index.html` から `index.php` に変えたときにも起きた（[002](002_complete-schedule.md)）。

### 2. `public` フォルダーが大文字の `Public` で作られていた
- 起きたこと：Copilot が `show-table.php` を作ったとき、ファイルが大文字の `Public` フォルダーに置かれていた。Windows は大文字と小文字を区別しないので動くが、Git や Linux のサーバーでは `public` と `Public` は別のフォルダーとして扱われる。
- 修正：Copilot が確認中に気づき、中身はそのままでフォルダー名を小文字の `public` に戻した。
- 教訓：ファイルやフォルダーの名前は、大文字・小文字までそろえる。

## 気づき・メモ
- Copilot は動作確認で、タイトルに `<script>` を含むテスト予定を登録していた。それが画面でプログラムとして動かず、文字として表示されることを確かめていた（XSS 対策の確認）。
- そのとき DB には本物の予定が1件あったので、それは残し、テスト用の予定だけを追加・削除して確認していた。
- storymap の `v` は「1つ下の段へ（後回し）」という意味なので、この項目は本来ウォーキングスケルトンの段には入らない（[001](001_delete-schedule.md) の計画時に確認した）。Copilot は「`v` マークから選ぶなら」とこの項目を勧めていて、`v` の意味を知らないまま選んだ可能性がある（推測）。ただ、登録した予定を目で確かめる手段として先に作ったのは役に立った。
