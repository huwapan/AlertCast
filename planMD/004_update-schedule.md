# 004 既に入力されている予定を変更する

- ストーリー：[docs/storymap.md](../docs/storymap.md) の「変更 > 予定を変更する > 既に入力されている予定を変更する」
- ブランチ：`feature/update-schedule`
- 状態：実装済み（ブラウザでの確認待ち）

## 背景
- ウォーキングスケルトンで残っているのは **変更** だけ。これができると、スケルトンの段がすべてそろう。
- 編集ページ（`schedule-edit.html`）には「予定の変更フォーム」が、まだ仮の文字として残っている。

## 決めたこと
- 流れは **予定を選ぶ → 変更フォームで直す → 保存**。削除と同じく、編集ページのリンクから変更用のページに移動する（一覧ページ `show-table.php` は見るためのページのまま）。
  1. `update-schedule-form.php`：変更する予定を一覧から1つ選んで「選択した予定を変更」を押す
  2. `update-schedule-form.php?id=番号`：選んだ予定の今の内容が入った変更フォームが出る。直して「変更を保存」を押す
  3. 保存できたら一覧に戻り、「予定を変更しました。」と表示する
- 変更できる項目は、登録と同じ **タイトル・開始日時・終了日時・優先度**。
- 変更できるのは、削除していない時間指定予定すべて。**完了済みの予定も変更でき、完了の記録はそのまま残す**（打ち間違いを直したいときなどに使える）。一覧には「状態」（完了・未完了）も出す。
- 入力のチェックは登録と同じにする。登録の処理（`src/schedule-create.php`）にあるチェックを、新しい `src/schedule-input.php` の関数に切り出して、登録と変更の両方で使う。
- 変更したら `updated_at` に日本時間の変更日時を入れる。
- エラーのとき：
  - POST 以外は 405、`id` が不正なら 422、入力が正しくなければ 422、対象がない（削除済みを含む）なら 404、DB エラーは 500
  - 入力のエラーのときは「変更フォームに戻る」リンクで、同じ予定の変更フォームに戻れるようにする

## ステップ
- [x] 1. ブランチ作成と計画書の保存（003 の状態を「マージ済み」に直す）
- [x] 2. 入力のチェックを `src/schedule-input.php` に切り出す
  - `parseLocalDateTime()`：フォームの日時（`2026-11-26T14:40`）を保存用の形（`2026-11-26 14:40:00`）にする（`schedule-create.php` から移す）

## 気づき・メモ
- 入力のチェックを関数に切り出すときは、先に登録の動きを変えないことを決めておき、切り出したあとに登録のテストもした。共通にした部分を直すと、登録と変更の両方に影響するため。
- 予定を選ぶ一覧のフォームは、`method="get"` で同じページを `?id=番号` 付きで開くようにした。データを書きかえない操作なので POST にしなくてよく、変更フォームの URL をそのまま開き直すこともできる。
- 保存されている日時（`2026-11-26 14:40:00`）は、そのままでは日時の入力欄（`datetime-local`）に入らない。`formatForDateTimeInput()` で `2026-11-26T14:40` の形に戻してから入れた。
- これでウォーキングスケルトンの段（入力・変更・想起・確認・削除）がすべてそろった。
