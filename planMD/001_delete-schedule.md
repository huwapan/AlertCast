# 001 予定を削除する（論理削除）

- ストーリー：[docs/storymap.md](../docs/storymap.md) の「削除 > 予定を取り消す > 予定を削除する」
- ブランチ：`feature/delete-schedule`
- 状態：実装済み（ブラウザでの確認と PR がまだ）

## 背景
- ウォーキングスケルトン（各機能の最小限を端から端までつなげたもの）を進めている。
- storymap の記号：`^` は1つ上の段へ、`v` は1つ下の段へ（後回し）。そのため「提案」「改善」はスケルトンに含めない。
- スケルトンの残り：**削除**、変更、想起（今日の予定と期限超過）、確認（完了ボタン）。
- 削除から作る理由：一覧の各行に「ID付きボタン → POST → リダイレクト」の形を作れば、「完了」「変更」でも同じ形を使い回せる。

## 決めたこと
- 削除方式は **論理削除** にする。行は消さず、`deleted_at` 列に削除日時を入れて一覧から隠す。あとで「復元」機能を作れるようにするため。
- 日時は `Asia/Tokyo` の `Y-m-d H:i:s` 形式で保存する（[ProjectMemo](../docs/ProjectMemo.md) に合わせる）。

## 失敗したことと修正したこと

### 1. マイグレーションが 001 しか実行されない作りだった（計画時に発見）
- 起きたこと：`src/Data.php` の `applyDatabaseMigrations()` に `001_create_schedules.sql` というファイル名が直接書かれていた。そのため `002_...sql` を追加しても実行されない状態だった。
- 修正：`database/migrations/*.sql` を `glob()` で全部取り出し、ファイル名順に並べて、まだ適用していないものだけを実行するように変えた。
- 確認：既存のDBでは 001 は飛ばされ、002 だけが適用された。新しく作ったDBでは 001 → 002 の順に適用された。
- 教訓：ファイル名などを直接書いておくと、2つ目を追加したときに動かない。増えていくものは「フォルダの中を全部読む」作りにしておく。

### 2. エラー画面の確認で、本文が空に見えた
- 起きたこと：タイトル空で登録したときの 422 の画面を curl で確かめたら、本文が何も表示されなかった。
- 原因：アプリの不具合ではなく、curl に付けた `-o /dev/stdout`（出力先を画面にする指定）が Windows の Git Bash ではうまく動かなかった。
- 修正：`-o /dev/stdout` を外して実行し直したら、本文が正しく表示された。アプリのコードは変更していない。
- 教訓：結果がおかしいときは、アプリを直す前にテストのやり方が正しいかを先に疑う。

### 3. curl で登録したテスト予定のタイトルが文字化けした
- 起きたこと：curl のコマンドに日本語のタイトル「削除テスト予定」を直接書いて登録したら、DB に文字化けしたタイトルで保存された。
- 原因：Windows の curl は、コマンドに直接書いた日本語を UTF-8 ではなく Shift_JIS（Windows の日本語の古い文字コード）に変えて送ってしまう。DB の中身を16進数で見ると `8DED…` で、これは Shift_JIS の「削」だった。ブラウザは UTF-8 で送るので、アプリの不具合ではない。
- 修正：送る内容を UTF-8 のファイルに保存し、`curl --data-binary @ファイル名` で送り直した。日本語のタイトルが一覧に正しく表示され、そのまま削除できることも確認した。文字化けしたテスト予定は、テスト後にDBをバックアップから戻して消した。
- 教訓：Windows の curl で日本語を送って試すときは、コマンドに直接書かずにファイルから送る。

### 4. 計画書の置き場所を変えた
- 起きたこと：最初は計画を Claude Code 側の計画ファイルにだけ書いていて、リポジトリには残らない状態だった。
- 修正：プロジェクト直下に `planMD/` フォルダを作り、このファイルとして保存して、Git で管理するようにした。
