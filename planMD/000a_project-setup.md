## 決めたこと
- **ファイル構成**：Git で管理しやすいように、役割ごとにフォルダーを分ける。
  - `public/`：ブラウザーに公開するページと CSS
  - `src/`：PHP の処理
  - `docs/`：要件や設計のメモ
  - `database/migrations/`：テーブルを作る SQL
- **ファイル名**：小文字とハイフンの形にそろえる（`ScheduleEdit.html` → `schedule-edit.html`）。
- **予定の種類**：次の3種類に分けて、1つのテーブル（`schedules`）で管理する（`docs/ProjectMemo.md` に記載）。
  - 時間内で終わる予定（`time_block`）：タイトル・開始日時・終了日時・優先度が必須
  - 一日単位の予定（`all_day`）：日付ごとに1件
  - 期限で終わらせる予定（`deadline`）：タイトル・開始日・終了日が必須。優先度は任意
- **データベース**：SQLite を使う。外部のサービスは不要で、PHP の `pdo_sqlite` 拡張があればファイル1つで動く。
- **Git に入れないもの**：予定のデータが入る `database/*.sqlite` は `.gitignore` で除外する。
- **コミットの単位**：「機能を一つ作るごとにコミットしたい」と決めた（11/12 15:54 に Copilot へ伝えた）。

## 失敗したことと修正したこと

### 1. CSS の読み込み先が実際の場所と違っていた
- 起きたこと：最初の `index.html` は `href="index.css"` で CSS を読み込もうとしていたが、ファイルは `css/index.css` にあった。編集ページ・閲覧ページへ移動するリンク先も設定されていなかった。
- 修正：ファイル構成を整理するとき（`b5a6f0c`）に、CSS の参照先とリンク先を直した。
- 教訓：ファイルを移動したり作ったりしたら、そのファイルを参照している場所も確かめる。

### 2. SQL のコメントを `//` で書いていた
- 起きたこと：`001_create_schedules.sql` のコメントを、JavaScript や PHP と同じ `//` で書いていた（`abb74ac` `5eadc5b`）。SQL では `//` はコメントにならないので、このままでは SQL を実行するとエラーになる。
- 修正：PHP からデータベースを作る処理を作るとき（`8bdc3c7`）に、Copilot が SQL を試しに実行して気づき、すべて `--` に直した。
- 教訓：コメントの書き方は言語ごとに違う。SQL は `--`、PHP と JavaScript は `//`、HTML は `<!-- -->`。

### 3. PHP が PC に入っていなくて、PHP のチェックができなかった
- 起きたこと：`Data.php` を作った時点では PHP の CLI（コマンドで動かす PHP）が PC になく、文法チェックもデータベースの作成も試せなかった。
- 修正：公式の PHP 8.5.12（x64）をユーザーのフォルダーに入れて PATH に登録し、`pdo_sqlite` を有効にした。その後 `Data.php` から実際に `database/alertcast.sqlite` を作れることを確かめた。
- 教訓：コードを書く前に、それを動かす環境（ここでは PHP と `pdo_sqlite`）があるかを確かめる。手順は README の「実行環境の準備（Windows）」にまとめた。

### 4. コミットの区切りを決めずに作業を進めていた
- 起きたこと：Copilot が `Data.php` の作成と確認を続けていたが、どこでコミットするかを決めていなかった。
- 修正：作業を一度止めて「機能一つ作るごとにコミットしたい」と伝え、データベースの準備をひとまとまりとしてコミットした（`8bdc3c7`）。
- 教訓：作業を始める前に、どこまでを1回のコミットにするかを決めておく。
