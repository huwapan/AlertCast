# 002 予定完了を通知を出してボタン操作で確認する

- ストーリー：[docs/storymap.md](../docs/storymap.md) の「確認 > 予定完了を確認する > 予定完了を通知を出してボタン操作で確認する」
- ブランチ：`feature/complete-schedule`
- 状態：実装中

## 背景
- ウォーキングスケルトンの残りは、**確認（完了）**、想起（今日の予定と期限超過）、変更。
- 完了から作る理由：想起の「期限を超過している予定を教える」は、予定が完了したかどうかが分からないと判定できないため。

## 決めたこと
- 完了の操作は **ホーム画面に通知を出して、その場のボタンで行う**（storymap の「通知を出してボタン操作で確認する」に合わせる）。
- 通知に出す予定：終了日時を過ぎていて、まだ完了も削除もしていない時間指定予定。
- ホームは DB を読む必要があるので、`index.html` を `index.php` に名前を変える（`git mv` で履歴を残す）。
- 完了日時は `completed_at` 列（001 で作成済み）に `Asia/Tokyo` の `Y-m-d H:i:s` で記録する。マイグレーションは不要。
- `show-table.php`（予定一覧）は見るためのページのまま。完了したかどうかが分かるように「状態」列だけ足す（ボタンは付けない）。

## ステップ
- [x] 1. ブランチ作成と計画書の保存
- [ ] 2. `public/index.html` を `public/index.php` に名前を変え、`index.html` へのリンクをすべて `index.php` に直す
- [ ] 3. 完了処理 `public/complete-schedule.php` と `src/schedule-complete.php` を追加
  - POST 以外は 405、`id` が不正なら 422、対象がない（完了済み・削除済みを含む）なら 404、DBエラーは 500
  - 成功したら `index.php?completed=1` へリダイレクト（303）
- [ ] 4. ホーム `index.php` の上部に「終わった予定があります。完了しましたか？」の通知と、予定ごとの「完了」ボタンを追加
- [ ] 5. `show-table.php` に「状態」（完了・未完了）列を追加
- [ ] 6. storymap・README・この計画書を更新

## 確認方法
- [ ] 変更した PHP ファイルに `php -l`（文法チェック）を実行する
- [ ] `/` と `index.php` でホームが表示され、ほかのページの「ホーム」リンクが `index.php` に向いている
- [ ] 終了日時が過去の予定は通知に出て、未来の予定は出ない
- [ ] 「完了」を押すとホームに戻って「完了にしました」と表示され、通知から消える。DB に `completed_at` が入る
- [ ] 予定一覧の「状態」が「完了」になる
- [ ] 異常系：GET は 405、`id=abc` は 422、完了済み・削除済みの ID は 404
- [ ] ブラウザで見た目を確認する（手動確認）
